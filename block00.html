Introducció del bloc

Abans de tocar dades, muntem un entorn mínim i entenem com QGIS gestiona rutes, projectes i scripts.

Aquest bloc evita el “bootstrap sense context”. En programació, “bootstrap” vol dir fer la posada en marxa inicial d’un projecte (preparar l’entorn bàsic perquè tot funcioni).

Tot s’explica des de la interfície de QGIS: panell Navegador, Consola Python i Editor. L’objectiu és que l’alumne pugui arrencar sense dependre de terminals externs.

Resultat esperat: estructura de carpetes llesta, concepte de Project Home clar i un primer contacte real amb dades (preview de 5 files).

Jerarquia: primer veuràs les subseccions 0.1–0.5 (guia pas a pas), i just després de cada subsecció trobaràs els exercicis (scripts) associats.

0.1 Preparació a QGIS

Subsecció del Bloc 0 · Estructura i projecte

Objectiu

Crear l’estructura base del projecte des de QGIS i deixar a punt el Project Home per treballar amb rutes relatives.

Què aprendràs

  • Fer servir el panell Navegador per crear carpetes del projecte.
  • Desar el projecte a l’arrel i entendre el Project Home Path.

Passos a QGIS

  1. Obre el panell Navegador. Fes click amb botó dret per crear la carpeta arrel del curs.
  2. A dins de l'arrel de la carpeta del curs crea les carpetes: dades/entrada, resultats, tools, exercicis.

Com obrir la Consola Python i l’Editor

  1. Ves a Plugins → Python Console.
  2. A la consola, clica la icona d’Editor (llapis).
  3. S’obrirà l’editor integrat per crear o obrir scripts.

Com crear i desar un script

  1. Des de l’Editor, crea un fitxer nou.
  2. Desa’l dins exercicis/00_bootstrap/.
  3. Executa’l amb el botó Run script (▶).

0.3 Funcions + mòduls: per què existeix tools

Subsecció del Bloc 0 · Reutilització mínimament viable

Objectiu

Entendre què és un mòdul i per què centralitzem funcions reutilitzables a tools.

Què aprendràs

  • Què significa “importar el teu propi mòdul”.
  • Per què __init__.py converteix una carpeta en un paquet de Python.
  • Per què evitem copiar i enganxar codi a cada script.

Com funciona l’estructura d’un projecte Python

Python organitza el codi en mòduls (fitxers .py) i paquets (carpetes amb __init__.py).

  • Mòdul = un fitxer .py. Es pot importar amb import nom_modul.
  • Paquet = carpeta amb __init__.py. Permet from paquet import modul.
  • __init__.py pot estar buit: només indica “aquí hi ha un paquet”.
  • __main__.py s’executa si llances el paquet amb python -m paquet (no cal per aquest curs, però és útil saber-ho).
  • if __name__ == "__main__" defineix el punt d’entrada quan executes un fitxer directament.

Exemple d’estructura del curs

arrel_del_curs/
    dades/
        entrada/
    resultats/
    tools/
        __init__.py
        config.py
        csv_utils.py
    exercicis/
        00_bootstrap/
            ex00_03_utils_modules.py

Idea clau: els scripts d’exercicis importen utilitats de tools. Això evita repetir codi i manté el projecte ordenat.

Imports típics (què passa per sota)

  • from tools import config busca la carpeta tools a l’arrel del projecte.
  • Si el Project Home és correcte, QGIS sap on és l’arrel i els imports funcionen.
  • Si falta __init__.py, Python no tracta tools com a paquet i l’import falla.

Passos a QGIS

  1. Al panell Navegador, crea tools/__init__.py.
  2. Entén que tools és un paquet local del projecte.

Què comprovar

  • El fitxer __init__.py apareix a la carpeta tools.
  • Si falta, els imports com from tools import config fallaran.

Errors típics

  • Crear el fitxer fora de la carpeta tools.
  • Escriure’l amb un altre nom (ha de ser exactament __init__.py).

És normal que aquest concepte sembli abstracte ara: el farem servir constantment als blocs següents.

"""Exercici 0.3 — Funcions + mòduls: per què existeix tools.

Objectiu:
- Entendre què és un mòdul i per què el reutilitzem.
- Comprovar que tools/__init__.py existeix.
- Intentar importar tools.config i donar instruccions clares si falla.
"""

from pathlib import Path

# Intentem usar QGIS per trobar l'arrel del projecte (Project Home)
try:
    from qgis.core import QgsProject
except Exception:
    QgsProject = None


def print_header(text):
    print("=" * 60)
    print(text)
    print("=" * 60)


print_header("EXERCICI 0.3 — tools i imports")

# 1) Localitzem l'arrel del projecte.
#    Si QGIS està obert, prioritzem Project Home.
root = None
if QgsProject is not None:
    try:
        home = QgsProject.instance().homePath()
        if home:
            root = Path(home)
    except Exception:
        root = None

# Fallback suau: pujem des de la ubicació de l'script

    root = Path(__file__).resolve().parents[2]

tools_dir = root / "tools"
init_file = tools_dir / "__init__.py"

print("Arrel del projecte:", root)
print("Carpeta tools:", tools_dir)

# 2) Comprovem que la carpeta tools existeix
if not tools_dir.exists():
    print("ERROR -> No existeix la carpeta tools")
    print("SOLUCIÓ -> Crea-la des del panell Navegador de QGIS.")
    raise SystemExit(1)

# 3) Comprovem si existeix tools/__init__.py
if not init_file.exists():
    print("ERROR -> No s'ha trobat tools/__init__.py")
    print("SOLUCIÓ -> Crea el fitxer des del panell Navegador de QGIS:")
    print("  1) Clic dret a la carpeta tools")
    print("  2) Nou fitxer")
    print("  3) Nom del fitxer: __init__.py")
    raise SystemExit(1)
else:
    print("OK -> tools/__init__.py existeix")



print("OK -> Exercici 0.3 completat.")

"""Configuració mínima del curs (rutes base)."""

from pathlib import Path


def _get_project_root() -> Path:
    """Detecta l'arrel del projecte (prioritza QGIS Project Home)."""
    try:
        from qgis.core import QgsProject

        project = QgsProject.instance()
        home = project.homePath()
        if home:
            return Path(home)
        project_file = project.fileName()
        if project_file:
            return Path(project_file).parent
    except Exception:
        pass

    # Fallback: puja des de tools/ cap a l'arrel del projecte
    try:
        return Path(__file__).resolve().parents[1]
    except Exception:
        return Path.cwd()


def as_posix(path: Path) -> str:
    """Converteix un Path a string absolut amb forward slashes."""
    return str(path.resolve().as_posix())


_ROOT = _get_project_root()

# Rutes base (mínim viable)
ROOT_DIR = as_posix(_ROOT)
DADES_DIR = as_posix(_ROOT / "dades")
ENTRADA_DIR = as_posix(_ROOT / "dades" / "entrada")
RESULTATS_DIR = as_posix(_ROOT / "resultats")

# Fitxers d'entrada (primer ús real de variables)
METEOCAT_INPUT = as_posix(Path(ENTRADA_DIR) / "Precipitacio_Olot_METEOCAT.csv")
AEMET_INPUT = as_posix(Path(ENTRADA_DIR) / "Precipitacio_Olot_AEMET.csv")

"""Utilitats mínimes per previsualitzar CSV (sense dependències externes)."""

import csv
from pathlib import Path
from typing import Optional, Union


def _open_text_for_read(path: Union[str, Path], encoding: str):
    """Obre un fitxer amb encoding i fa fallback a utf-8-sig si hi ha BOM."""
    try:
        return open(path, "r", encoding=encoding, newline="")
    except UnicodeDecodeError:
        if encoding.lower() != "utf-8-sig":
            return open(path, "r", encoding="utf-8-sig", newline="")
        raise


def preview_csv(path: Union[str, Path], max_rows: int = 5, title: Optional[str] = "") -> None:
    """Mostra columnes i les primeres files d'un CSV.

    - No carrega tot el fitxer a memòria.
    - Gestiona encoding amb fallback.
    - Si el fitxer no existeix, mostra un missatge didàctic.
    """
    if title:
        print(title)

    p = Path(path)
    if not p.exists():
        print(f"AVÍS -> No existeix el fitxer: {p}")
        print("SOLUCIÓ -> Copia el CSV a dades/entrada i torna-ho a provar.")
        print("-" * 60)
        return

    with _open_text_for_read(p, encoding="utf-8") as f:
        reader = csv.DictReader(f, delimiter=",")

        print("Columnes:")
        fieldnames = list(reader.fieldnames) if reader.fieldnames else []
        print(fieldnames)

        print(f"Primeres {max_rows} files:")
        for i, row in enumerate(reader):
            print(row)
            if i >= max_rows - 1:
                break

    print("-" * 60)

0.5 Primer contacte amb dades: preview de 5 files

Subsecció del Bloc 0 · Entendre el problema abans d’automatitzar

Objectiu

Visualitzar un exemple petit i realista per entendre per què cal estandarditzar dades de Meteocat i AEMET.

Què aprendràs

  • Detectar columnes i formats incompatibles entre fonts.
  • Veure problemes típics de decimals i dates.

Exemple Meteocat (capçalera real)

EMA DATA X Y PPT
YB 21/07/2016 456316 4670799 0
YB 22/07/2016 456316 4670799 5

Altres columnes Meteocat: VVM10vec, VVM10, DVM10u, DVM10, VVX10, Data Extrem VVX10, DVVX10, Data Extrem DVVX10.

Exemple AEMET (capçalera real)

INDICATIVO AÑO MES NOMBRE ALTITUD LONGITUD LATITUD P1 P2 P3 P4 P5
0390D 1992 1 OLOT (PARC NOU) 440 228471 421015 0 0 0 0 0
0390D 1992 2 OLOT (PARC NOU) 440 228471 421015 0 0 0 0 0

Altres columnes AEMET: P6, P7, ..., P31 (precipitació per dia del mes).

Diferències clau (què ens obliga a netejar)

  • Estructura temporal: Meteocat és diari (una fila per dia). AEMET és mensual i ve “ample” amb P1..P31.
  • Data: Meteocat té DATA com a data completa; AEMET separa AÑO i MES i reparteix els dies a columnes.
  • Precipitació: Meteocat usa PPT; AEMET reparteix valors a P1..P31 (cal despivotar).
  • Coordenades: Meteocat fa servir X/Y, AEMET té LONGITUD/LATITUD (cal harmonitzar CRS i formats).

Passos a QGIS

  1. Explora els CSV des del panell Navegador.
  2. Identifica columnes de data i precipitació.
  3. Observa diferències de formats entre fonts.

Què comprovar

  • Les dates no sempre estan en el mateix format.
  • Els decimals poden usar coma o punt.
  • Hi ha valors buits o nuls.

Errors típics

  • Suposar que totes les dates ja estan normalitzades.
  • Tractar “7,8” com a text sense convertir a número.

Sobre els floats: la precipitació és un número real (mm). Si el separador és coma, cal convertir-lo abans de calcular mitjanes o totals.

Sobre les dates: pots trobar YYYY-MM-DD, DD/MM/YYYY, columnes separades o timestamps. Normalitzar dates és obligatori per ordenar sèries temporals.
