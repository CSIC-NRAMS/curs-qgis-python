Benvinguda 👋

Com treballarem aquests exercicis (pas a pas i sense pressa)

Benvingut/da! En aquesta pàgina tens els scripts del curs ordenats per fases. L’objectiu no és “memoritzar Python”, sinó aprendre a llegir dades reals, netejar-les i estandarditzar-les perquè després les puguem fer servir a QGIS sense sorpreses.

Si és el teu primer contacte amb Python, no pateixis: cada exercici introdueix una idea nova i la repetirem amb exemples. L’ordre importa: primer entenem el CSV, després netegem números i dates, i finalment fem la part “SIG” (coordenades, CRS i exportació).

Consell: executa els scripts en ordre i mira sempre el fitxer de sortida a la carpeta de resultats. El millor indicador que ho estàs fent bé és veure com el CSV va millorant a cada pas.

Context del projecte

Què estem estandarditzant i per què

Treballarem amb dues fonts diferents de precipitació (Meteocat i AEMET). Tot i que parlen del mateix fenomen, no tenen el mateix format: canvia la manera d’escriure la data, el sistema de coordenades i fins i tot les unitats de precipitació.

La nostra feina serà crear un dataset estàndard (mateixes columnes, mateix format i mateix CRS) per poder unir-ho tot i portar-ho a QGIS. Aquest tipus de “traducció” entre formats és el dia a dia quan treballem amb dades geogràfiques reals.

     open_csv_writer(PAS3_OUT, fieldnames=columnes) as escriptor:

🔍 Anàlisi Tècnica

Objectiu: convertir totes les dates al mateix format (YYYY-MM-DD). Això permet ordenar, filtrar i unir dades de fonts diferents sense confusions.

Per què ISO? perquè és un estàndard internacional i, a més, ordena bé alfabèticament (text) i cronològicament (temps).

Convertim qualsevol format de data d'entrada (DD/MM/YYYY) a l'estàndard ISO 8601 (YYYY-MM-DD). Això permet ordenar cronològicament les dades com a text simple.

import os
import sys

ROOT_DIR = os.path.dirname(os.path.dirname(__file__))
if ROOT_DIR not in sys.path:
    sys.path.append(ROOT_DIR)

from utils.config import PAS3_OUT, PAS4_OUT, RESULTATS_DIR
from utils.csv_utils import ensure_dir, open_csv_reader, open_csv_writer, preview_csv
from utils.qgis_utils import get_utm31_to_wgs84_transformer, transform_utm_to_lonlat

columnes = ["EMA", "DATA", "X", "Y", "PPT", "lon", "lat"]
xform = get_utm31_to_wgs84_transformer()
files_llegides = 0
files_escrites = 0
files_saltades = 0

ensure_dir(RESULTATS_DIR)

with open_csv_reader(PAS3_OUT, encoding="utf-8") as lector, \
     open_csv_writer(PAS4_OUT, fieldnames=columnes) as escriptor:

    for fila in lector:
        files_llegides += 1
        try:
            x = float(fila.get("X"))
            y = float(fila.get("Y"))
        except:
            files_saltades += 1
            continue

        try:
            lon, lat = transform_utm_to_lonlat(x, y, xform)
        except:
            files_saltades += 1
            continue

        nova_fila = dict(fila)
        nova_fila["lon"] = lon
        nova_fila["lat"] = lat
        escriptor.writerow(nova_fila)
        files_escrites += 1

preview_csv(PAS4_OUT, max_rows=5, title="Preview meteocat_pas4.csv")
print(f"OK -> creat {PAS4_OUT}")

🔍 Anàlisi Tècnica

Imports PyQGIS: utilitzem QGIS per transformar coordenades d’UTM (metres) a WGS84 (graus). Això ens dona lon i lat per poder carregar el CSV com a punts.

Pas clau: la transformació només té sentit si X i Y són números vàlids. Per això hem netejat i filtrat abans.

Afegim les columnes lon i lat. Utilitzem un bloc try/except per assegurar que si una coordinada concreta és corrupta, no aturi tot el procés.

ex06_final_estandarditzat.py

📥 Descarregar Script
Fase: Mapeig final de camps
import os
import sys

ROOT_DIR = os.path.dirname(os.path.dirname(__file__))
if ROOT_DIR not in sys.path:
    sys.path.append(ROOT_DIR)

from utils.config import PAS4_OUT, STD_OUT, STD_FIELDS, RESULTATS_DIR
from utils.csv_utils import ensure_dir, open_csv_reader, open_csv_writer, preview_csv

files_llegides = 0
files_escrites = 0
files_saltades = 0

ensure_dir(RESULTATS_DIR)

with open_csv_reader(PAS4_OUT, encoding="utf-8") as lector, \
     open_csv_writer(STD_OUT, fieldnames=STD_FIELDS) as escriptor:

    for fila in lector:
        files_llegides += 1

        ema = (fila.get("EMA") or "").strip()
        data = (fila.get("DATA") or "").strip()
        ppt = fila.get("PPT")
        lon = fila.get("lon")
        lat = fila.get("lat")
        x_utm = fila.get("X")
        y_utm = fila.get("Y")

        if not (ema and data and lon and lat and x_utm and y_utm):
            files_saltades += 1
            continue

        nova_fila = {
            "source": "METEOCAT",
            "station_id": ema,
            "station_name": f"Olot (Meteocat EMA {ema})",
            "date": data,
            "precip_mm": ppt,
            "lon": lon,
            "lat": lat,
            "x_utm": x_utm,
            "y_utm": y_utm,
            "alt_m": ""
        }
        escriptor.writerow(nova_fila)
        files_escrites += 1

preview_csv(STD_OUT, max_rows=5, title="Preview meteocat_std.csv")
print(f"OK -> creat {STD_OUT}")

🔍 Anàlisi Tècnica

Què vol dir “estandarditzar” aquí? Crear un fitxer final amb les mateixes columnes i el mateix significat, independentment de la font. Això és el que farà possible el “merge” final.

Mapeig de camps: aquí reanomenem i reordenem camps (ex: EMA → station_id) i fixem source a “METEOCAT”.

Creem el fitxer final amb l'estructura definitiva (source, station_id, etc.). Aquí "hardcodegem" el valor de source a "METEOCAT".

ex08_aemet_despivot_pas1.py

📥 Descarregar Script
Fase: Transformació Wide to Long
import os
import sys

ROOT_DIR = os.path.dirname(os.path.dirname(__file__))
if ROOT_DIR not in sys.path:
    sys.path.append(ROOT_DIR)

from utils.config import AEMET_INPUT, AEMET_PAS1_OUT, RESULTATS_DIR
from utils.csv_utils import ensure_dir, open_csv_reader, open_csv_writer, preview_csv

columnes = [
    "INDICATIVO", "NOMBRE", "ALTITUD", "LONGITUD", "LATITUD",
    "AÑO", "MES", "DAY", "P_TENTHS"
]
files_llegides = 0
files_escrites = 0

ensure_dir(RESULTATS_DIR)

with open_csv_reader(AEMET_INPUT) as lector, \
     open_csv_writer(AEMET_PAS1_OUT, fieldnames=columnes) as escriptor:

    p_cols = [c for c in lector.fieldnames if c.startswith("P") and c[1:].isdigit()]

    for fila in lector:
        files_llegides += 1
        for col in p_cols:
            val = fila.get(col)
            if val is None or str(val).strip() == "":
                continue

            day_num = int(col.replace("P", ""))
            
            nova_fila = {
                "INDICATIVO": fila.get("INDICATIVO", ""),
                "NOMBRE": fila.get("NOMBRE", ""),
                "ALTITUD": fila.get("ALTITUD", ""),
                "LONGITUD": fila.get("LONGITUD", ""),
                "LATITUD": fila.get("LATITUD", ""),
                "AÑO": fila.get("AÑO", ""),
                "MES": fila.get("MES", ""),
                "DAY": day_num,
                "P_TENTHS": val
            }
            escriptor.writerow(nova_fila)
            files_escrites += 1

preview_csv(AEMET_PAS1_OUT, max_rows=5, title="Preview aemet_pas1_long.csv")
print(f"OK -> creat {AEMET_PAS1_OUT}")

🔍 Anàlisi Tècnica

Concepte nou: “despivotar” (de wide a long). Passem de columnes P1…P31 a moltes files, una per dia.

Per què és necessari? perquè el nostre estàndard final treballa amb una data per fila. Així podem ordenar i unir amb Meteocat.

Detectem dinàmicament les columnes P1...P31. Per a cada fila original (que representa un mes), generem múltiples files de sortida (una per a cada dia amb dades). Això es coneix com "despivotar" o "melt".

        data = build_date(fila.get("AÑO"), fila.get("MES"), fila.get("DAY"))

        if data is None:
            continue

        nova_fila = dict(fila)
        nova_fila["date"] = data.isoformat()
        escriptor.writerow(nova_fila)
        files_escrites += 1

preview_csv(AEMET_PAS2_OUT, max_rows=5, title="Preview aemet_pas2_dates.csv")
print(f"OK -> creat {AEMET_PAS2_OUT}")

🔍 Anàlisi Tècnica

Reconstrucció de la data: AEMET separa any, mes i dia. Nosaltres els unim per crear un camp date en ISO.

Control d’errors: alguns dies no existeixen (ex: 30 de febrer). En aquests casos descartem la fila per evitar dates impossibles.

Reconstruïm la data completa a partir de columnes separades (ANY, MES, DIA). La funció build_date gestiona dies invàlids (com 30 de febrer) retornant None.

import os
import sys

ROOT_DIR = os.path.dirname(os.path.dirname(__file__))
if ROOT_DIR not in sys.path:
    sys.path.append(ROOT_DIR)

from qgis.core import QgsVectorLayer, QgsVectorFileWriter, QgsProject
from utils.config import MERGED_STD_OUT, GPKG_OUT, GPKG_LAYER, RESULTATS_DIR
from utils.csv_utils import ensure_dir

ensure_dir(RESULTATS_DIR)

# URI Màgica per carregar CSV sense GUI
uri = f"file:///{MERGED_STD_OUT}?delimiter=,&xField=lon&yField=lat&crs=EPSG:4326"

layer = QgsVectorLayer(uri, "precipitacio_olot", "delimitedtext")

if not layer.isValid():
    print("ERROR -> No s'ha pogut carregar la capa del CSV.")
else:
    QgsProject.instance().addMapLayer(layer)

    options = QgsVectorFileWriter.SaveVectorOptions()
    options.driverName = "GPKG"
    options.layerName = GPKG_LAYER
    options.fileEncoding = "UTF-8"

    QgsVectorFileWriter.writeAsVectorFormatV2(layer, GPKG_OUT, QgsProject.instance().transformContext(), options)

    print(f"OK -> GeoPackage creat: {GPKG_OUT}")
    print("OK -> Capa afegida al projecte QGIS.")

🔍 Anàlisi Tècnica

Últim pas SIG: convertim el CSV a un GeoPackage (format espacial estàndard) perquè QGIS i altres SIG el puguin llegir com una capa vectorial real.

Idea clau: un CSV és text; un GPKG és una base de dades espacial. Aquest canvi fa que el dataset sigui més robust i reutilitzable.

Utilitza l'API de QGIS per convertir el CSV en text pla a una base de dades espacial GeoPackage real, a punt per ser utilitzada en qualsevol SIG.
